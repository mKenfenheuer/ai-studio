What is this app doing?

There are two things you can do here. Usually you take a model someone else already trained and teach it your task using examples you choose — that is fine-tuning, and it takes minutes to hours. Or you can build a model from scratch, starting from random numbers, which is slower and only works for small models on one graphics card — but the result is entirely yours.

1

Pick a base model

A model that already understands language. Bigger ones are smarter but need more memory.

2

Pick your examples

A dataset of questions and good answers. The model learns the pattern in them — then you choose the format they are written in, normally the model's own.

3

Train

Your GPU repeatedly shows the model examples and nudges it toward better answers. You watch the error go down.

4

Use the result

Chat with it in the Playground, score it against a set of prompts, download it, or point other software at it — this studio speaks the OpenAI API, so anything with a “base URL” field can use your model. Get a key from your account.

Building from scratch

The same four steps, with two differences. There is no base model — you choose a size instead — and instead of examples you give it plain text to read. The honest part: a model needs roughly 20 words of text for every parameter it has before it finishes learning. On one graphics card that means small models, and the app will show you exactly where the limit falls rather than letting you find out overnight.

Words you will see

Loss
How wrong the model is. Training works when this goes down. It is the single number to watch.
LoRA
A trick that trains a tiny number of extra parameters instead of all billions of them. Much faster, needs far less memory, and works nearly as well.
Epoch
One complete pass through all your examples.
Step
One update to the model. Many steps make an epoch.
VRAM
Memory on your graphics card. The main limit on how big a model you can train.
Quantization
Storing the model with less precision so it fits in less memory. Slight quality cost, big memory saving.
Adapter
The small file your training produces. Combine it with the base model to get your fine-tuned model.
Overfitting
When the model memorises your examples instead of learning the pattern. Watch for loss that keeps dropping while results get worse.
Token
A chunk of text, usually part of a word. Models read and write tokens, not letters. Roughly four characters each.
Vocabulary
The full set of tokens a model knows. Built from your own text when you train from scratch.
From scratch
Training a model whose weights start as random noise, rather than adjusting one that already works.
Held-out loss
The loss measured on text the model was never trained on. The honest number: if it rises while training loss falls, the model is memorising. It is also the only loss that means anything when comparing two different runs.
Checkpoint
A snapshot of a run, saved every few minutes. If the machine restarts, training carries on from the last one instead of starting again from noise.
Prompt set
A saved list of questions, kept so that every model you train can be asked the same ones. The only way to answer “is this better than last week's?”
Adapter vs merged model
A fine-tune produces a small adapter that only works alongside the model it was trained on. Merging folds it in and gives you one complete model — bigger, but it runs anywhere on its own.
Sweep
The same run launched several times with one setting changed, so you can see which value was actually better instead of guessing.
Base model
A model that only continues text. It has not been taught to answer questions — that is what fine-tuning adds.
